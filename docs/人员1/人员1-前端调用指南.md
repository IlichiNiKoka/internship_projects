# 人员1 AI 应用编排——前端调用指南

本文面向人员5及其他前端开发者，描述当前代码中已经实现的
`/api/v1/assistant/*` 接口契约。需求边界和后端设计依据见
[人员1-AI应用编排需求与接口.md](人员1-AI应用编排需求与接口.md)。

## 1. 快速接入

开发服务默认地址为 `http://127.0.0.1:5000`，统一前缀为：

```text
/api/v1/assistant
```

建议前端始终请求相对路径，并通过同源部署或开发服务器代理转发 `/api`。
当前 Flask 应用没有启用跨域响应头，浏览器从其他源直接访问会受到 CORS 限制。

例如 Vite 开发代理可配置为：

```ts
// vite.config.ts（示例）
export default {
  server: {
    proxy: {
      "/api": "http://127.0.0.1:5000",
    },
  },
};
```

后端可在项目的 `data_process` 目录下用 `shixun` 环境启动：

```bash
conda run -n shixun python run.py
```

### 1.1 鉴权

- 开发/测试环境未配置 `ANALYTICS_ASSISTANT_API_KEY` 时，可以直接调用。
- 配置了该变量后，所有 `/api/v1/assistant/*` 接口（包括 `health`）都必须携带以下任一请求头：

```http
Authorization: Bearer <assistant-api-key>
```

或：

```http
X-Assistant-API-Key: <assistant-api-key>
```

生产环境如果没有配置该 key，接口会以 `503` 拒绝服务。

> 安全要求：不要把共享 API Key 写入 Vue/React/Vite 构建变量、浏览器源码、
> `localStorage` 或仓库。生产环境应由同源后端/BFF或反向代理完成用户鉴权并注入该请求头；
> 浏览器不应接触共享密钥。

### 1.2 统一响应外壳

所有成功和失败响应都使用相同外壳，HTTP 状态码与 `code` 一致：

```ts
export interface ApiEnvelope<T> {
  code: number;
  message: string;
  data: T | null;
  query_time: number;
  trace_id: string;
}
```

```json
{
  "code": 200,
  "message": "OK",
  "data": {},
  "query_time": 0.123,
  "trace_id": "d2b2d41e84674f17"
}
```

响应头还会返回 `X-Request-ID` 和 `X-Query-Time`。发生问题时，前端应展示或记录
`trace_id`，便于后端查日志。

`X-Request-ID` 与聊天请求体中的 `request_id` 用途不同：

| 字段 | 用途 | 是否影响业务去重 |
|---|---|---|
| `X-Request-ID` 请求头 | 单次 HTTP 链路追踪 | 否 |
| `request_id` 请求字段 | 同一会话内聊天请求幂等 | 是 |

## 2. 接口一览

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/v1/assistant/health` | 检查编排层和会话存储状态 |
| `GET` | `/api/v1/assistant/tools` | 获取六类工具及 LangChain 注册状态 |
| `POST` | `/api/v1/assistant/chat` | 新建对话、续聊、引用历史分析或同步生成报告 |
| `GET` | `/api/v1/assistant/sessions/{session_id}` | 恢复会话；可选返回原始分析结果 |
| `DELETE` | `/api/v1/assistant/sessions/{session_id}` | 删除会话 |
| `POST` | `/api/v1/assistant/sessions/{session_id}/reports` | 根据当前会话的一项、多项或全部分析生成报告 |
| `GET` | `/api/v1/assistant/sessions/{session_id}/reports/{report_id}` | 获取完整报告 |

所有 `POST` 请求必须发送 JSON 对象，并设置 `Content-Type: application/json`。
非法 JSON、JSON 数组、非 JSON Content-Type 和未知字段均返回 `400`。

当前没有“会话列表”“全局报告列表”“修改报告”或“删除报告”接口。前端必须自行保存
当前 `session_id`；已知会话下的报告摘要可以从会话恢复接口的 `reports` 获得，再逐份
调用报告详情接口。所有资源 ID 均由服务端生成，前端不要自行拼接。

共享 key 只提供接口级保护，当前也没有用户级 RBAC 或会话归属校验；`session_id` 本身
不是用户授权机制。多用户生产部署必须在 BFF/网关层补充用户身份和资源归属校验。

## 3. 聊天接口

### 3.1 请求

`POST /api/v1/assistant/chat`

```ts
export interface ChatRequest {
  message: string;             // 必填，非空白，长度 1~500
  session_id?: string | null;  // ses_ + 20 位小写十六进制
  analysis_id?: string | null; // ana_ + 20 位小写十六进制
  generate_report?: boolean;   // 默认 false；使用 JSON boolean
  request_id?: string | null;  // 8~64 位，首位字母或数字，其余可含 _-
}
```

新对话不要自行生成 `session_id`，省略该字段或传 `null`，使用响应中的服务端 ID：

```json
{
  "message": "2021年各医院的平均费用",
  "request_id": "4a6ec1e7-695b-43ba-a3f3-09984715f14b"
}
```

续聊时复用响应中的 `session_id`：

```json
{
  "message": "那按性别看呢",
  "session_id": "ses_0123456789abcdef0123",
  "request_id": "563730d5-e702-4aa0-87b7-54079f3a036c"
}
```

需要明确引用某一次历史分析时，同时传当前会话的 `analysis_id`：

```json
{
  "message": "解释这个结果",
  "session_id": "ses_0123456789abcdef0123",
  "analysis_id": "ana_0123456789abcdef0123",
  "request_id": "a1f06fb2-7618-497d-ac55-34f2dc1149c1"
}
```

本轮分析完成后同步生成单项报告：

```json
{
  "message": "按年龄组统计住院人次",
  "session_id": "ses_0123456789abcdef0123",
  "generate_report": true,
  "request_id": "61d6697e-e863-4131-8d03-a209afc6ca3a"
}
```

传入格式合法但不存在或已经过期的 `session_id` 会返回 `404`，不会用该 ID 静默新建会话。

### 3.2 `request_id` 幂等规则

浏览器的 `crypto.randomUUID()` 符合当前格式。推荐规则是：

1. 用户每次点击“发送”时生成一个新 `request_id`。
2. 请求超时、断网或前端无法确认是否收到响应时，用完全相同的请求体和同一个
   `request_id` 重试。
3. 如果已经收到 HTTP 200 且业务状态为 `failed`，用户点击“重新分析”时应生成新的
   `request_id`，否则服务端只会重放上次失败结果。
4. 同一个 `request_id` 不能用于不同的 `message`、`analysis_id` 或
   `generate_report`；违反时返回 `409`。
5. `request_id` 只在对应会话的 TTL 和已保留消息窗口内去重，不是全局永久键。

幂等命中后响应 `status` 为 `replayed`，不会重复执行 Spark 分析或重复生成报告。
首次创建会话时如果网络中断且前端没有拿到服务端 `session_id`，后续另建会话无法实现
跨会话去重；因此前端拿到首个响应后应立即保存 `session_id`。

### 3.3 响应类型

```ts
export type ChatStatus =
  | "completed"
  | "report_generated"
  | "context_summary"
  | "needs_clarification"
  | "unsupported"
  | "failed"
  | "replayed";

export interface ConversationMessage {
  id: string;
  role: "user" | "assistant";
  content: string;
  created_at: string; // UTC ISO-8601
  intent: string | null;
  analysis_id: string | null;
  report_id: string | null;
  metadata: Record<string, unknown>; // 扩展字段，前端不要写死完整结构
}

export interface IntentResult {
  query?: string;
  intent: string;
  intent_label?: string;
  confidence?: number;
  params: Record<string, unknown>;
  missing_required?: string[];
  downstream?: string;
  downstream_target?: string;
  matched_signals?: Record<string, string[]>;
  context_inherited?: boolean;
  classified_intent?: string;
}

export interface AnalysisRecord {
  id: string;
  message_id: string;
  query: string;
  intent: string;
  tool_name: string;
  tool_input: Record<string, unknown>;
  result?: {
    intent: string;
    tool: string;
    request: Record<string, unknown>;
    data: unknown;         // 人员3原始结果，结构随意图变化
    summary_data: unknown; // 摘要与指标卡使用的规范化事实
    provenance: Record<string, unknown>;
  };
  summary: {
    text?: string;
    llm_provider?: string;
    fell_back_to_mock?: boolean;
    empty_source?: boolean;
    hallucination?: { passed?: boolean; [key: string]: unknown };
  };
  attempts: number;
  elapsed_seconds: number;
  created_at: string;
}

export interface AssistantWarning {
  code: "TOOL_INVOCATION_FAILED" | "UNTRUSTED_SUMMARY" | "LLM_FALLBACK" | string;
  message?: string;
  tool?: string;
  attempts?: number;
  trace_id?: string;
  analysis_id?: string;
}

export interface ChatResult {
  session_id: string;
  status: ChatStatus;
  user_message: ConversationMessage;
  assistant_message: ConversationMessage;
  intent: IntentResult;
  analysis: AnalysisRecord | null;
  report: MedicalReport | null;
  warnings: AssistantWarning[];
  context: {
    referenced_analysis_id?: string | null;
    context_inherited?: boolean;
    reason?: string;
    missing?: string[];
    idempotency_key?: string;
    original_status?: Exclude<ChatStatus, "replayed">;
  };
  history_size: number;
}
```

`POST /chat` 的成功响应为 `ApiEnvelope<ChatResult>`。无论状态是哪一种，都应先把
`assistant_message.content` 作为助手消息展示，再按状态决定附加组件：

| `status` | 含义 | 前端建议 |
|---|---|---|
| `completed` | 新分析已完成；`report` 可能同时存在 | 展示文本；渲染 `analysis`，有 `report` 时再渲染报告 |
| `report_generated` | 使用已保存分析生成了报告，没有重跑分析 | 展示文本和 `report` |
| `context_summary` | 对历史结果重新解读，没有重跑分析 | 展示文本，可附上对应 `analysis` |
| `needs_clarification` | 缺少条件或没有可引用历史 | 保持输入框可用；兼容读取 `intent.missing_required` 与 `context.missing` |
| `unsupported` | 问题不在当前六类医疗能力内 | 展示支持范围，不渲染图表 |
| `failed` | 下游分析调用失败，但 HTTP 请求本身已正常处理 | 展示错误消息和“重新分析”；新尝试使用新 `request_id` |
| `replayed` | 相同幂等请求的已保存响应 | 按 `context.original_status` 和实际 `analysis/report` 渲染，并按消息 ID 去重 |

注意：`completed` 不保证 `report` 非空；同步报告仍保持 `completed` 状态。
`report_generated` 专指基于已有分析生成报告的对话路径。工具参数不足通常是
`needs_clarification`/HTTP 200，工具执行失败通常是 `failed`/HTTP 200，而不是 HTTP 4xx/5xx。

### 3.4 推荐调用封装

下面的实现假设浏览器通过同源代理访问，密钥由服务端处理：

```ts
const ASSISTANT_BASE = "/api/v1/assistant";

export class AssistantApiError extends Error {
  constructor(
    public readonly status: number,
    public readonly traceId: string,
    public readonly detail: unknown,
    message: string,
  ) {
    super(message);
  }
}

async function assistantRequest<T>(path: string, init: RequestInit = {}): Promise<T> {
  const headers = new Headers(init.headers);
  headers.set("Accept", "application/json");
  if (init.body) headers.set("Content-Type", "application/json");

  const response = await fetch(`${ASSISTANT_BASE}${path}`, {
    ...init,
    headers,
  });
  const body = (await response.json()) as ApiEnvelope<T>;

  if (!response.ok || body.code !== 200 || body.data === null) {
    throw new AssistantApiError(
      response.status,
      body.trace_id ?? response.headers.get("X-Request-ID") ?? "unknown",
      body.data,
      body.message || "请求失败",
    );
  }
  return body.data;
}

export function sendChat(
  request: ChatRequest,
  signal?: AbortSignal,
): Promise<ChatResult> {
  return assistantRequest<ChatResult>("/chat", {
    method: "POST",
    body: JSON.stringify(request),
    signal,
  });
}
```

页面发送逻辑示例：

```ts
let sessionId: string | null = localStorage.getItem("assistant_session_id");

async function submitMessage(message: string) {
  const requestId = crypto.randomUUID();
  const result = await sendChat({
    message,
    session_id: sessionId,
    request_id: requestId,
  });

  sessionId = result.session_id;
  localStorage.setItem("assistant_session_id", sessionId);
  return result;
}
```

同一会话的请求由服务端串行处理。前端也应在当前消息返回前禁用该会话的重复发送，
否则等待会话锁超过默认 30 秒可能返回 `429`。

## 4. 会话恢复与删除

### 4.1 恢复会话

```http
GET /api/v1/assistant/sessions/{session_id}
GET /api/v1/assistant/sessions/{session_id}?include_results=true
```

默认不返回 `analyses[].result`，适合恢复消息列表；报告也只返回摘要元数据：

```ts
export interface SessionResult {
  session_id: string;
  created_at: string;
  updated_at: string;
  version: number;
  messages: ConversationMessage[];
  analyses: AnalysisRecord[]; // include_results=false 时没有 result
  reports: Array<{
    report_id: string;
    title: string;
    generated_at: string;
  }>;
}
```

所有时间字段均为带时区的 UTC ISO-8601 字符串。`version` 当前只用于展示/诊断，接口
没有 `If-Match` 或客户端提交版本的协议，前端不要把它当作可用的乐观锁参数。

只有确实需要重新渲染原始分析数据时才使用 `include_results=true`，以免加载大结果。
要展示完整报告，应再调用报告详情接口。

会话默认保存 24 小时，可能因过期或容量限制被清理。恢复时如果收到 `404`，应清除
本地旧 `session_id`，提示“会话已过期”，下一条消息不传 `session_id` 以创建新会话。

### 4.2 删除会话

```http
DELETE /api/v1/assistant/sessions/{session_id}
```

成功数据：

```json
{
  "session_id": "ses_0123456789abcdef0123",
  "deleted": true
}
```

删除成功后再清理前端消息、报告和本地 `session_id`。不存在的会话返回 `404`。

## 5. 报告生成与获取

### 5.1 生成报告

```http
POST /api/v1/assistant/sessions/{session_id}/reports
```

指定一项或多项当前会话内的分析：

```json
{
  "analysis_ids": [
    "ana_0123456789abcdef0123",
    "ana_abcdef0123456789abcd"
  ],
  "title": "医院费用与再入院风险洞察"
}
```

- `analysis_ids` 最多 10 项；传空数组不合法，重复 ID 会被去重。
- 省略 `analysis_ids` 或传 `null` 表示使用当前会话的全部已保存分析。
- `title` 可省略，非空时最长 120 字符。
- 即使使用全部分析，服务端仍受报告分析数配置限制，默认最多取最近 10 项。
- 报告接口要求 JSON 对象；生成全部分析报告时也必须发送 `{}`，不能发送空请求体。
- `analysis_id` 只能引用当前会话；跨会话或不存在的 ID 返回 `404`。

该接口返回 `ApiEnvelope<MedicalReport>`。

前端“生成报告”按钮应优先调用本专用接口：它可精确选择分析并支持自定义标题。
自然语言中的报告命令采用启发式识别，而 `/chat` 的 `generate_report=true` 只能生成
默认标题，不适合替代确定性的报告按钮流程。会话没有任何分析时，本接口返回 `404`；
聊天中请求“生成刚才的报告”但没有历史，则返回 `needs_clarification`/HTTP 200。

### 5.2 获取报告

```http
GET /api/v1/assistant/sessions/{session_id}/reports/{report_id}
```

返回完整 `MedicalReport`。报告属于会话，不能跨会话读取。

## 6. 报告数据与渲染

```ts
export interface MedicalReport {
  schema_version: "1.0" | string;
  report_id: string;
  session_id: string;
  title: string;
  generated_at: string;
  source_analysis_ids: string[];
  executive_summary: string;
  sections: ReportSection[];
  charts: NeutralChartSpec[];
  warnings: AssistantWarning[];
  validation: {
    all_summaries_trusted: boolean;
    warning_count: number;
    source_count: number;
  };
  provenance: Array<{
    analysis_id: string;
    tool: string;
    tool_input: Record<string, unknown>;
    attempts: number;
    elapsed_seconds: number;
    called_at: string;
  }>;
  display: {
    supported_exports: string[]; // 当前只有 json
    default_layout: string;
  };
}

export interface ReportSection {
  section_id: string;
  analysis_id: string;
  intent: string;
  title: string;
  query: string;
  narrative: string;
  summary_validation: {
    trusted: boolean;
    llm_provider?: string;
    fell_back_to_mock: boolean;
    hallucination: Record<string, unknown>;
  };
  key_metrics: Array<{
    key: string;
    label: string;
    value: unknown;
    unit: string;
  }>;
  table: {
    columns: string[];
    rows: Array<Record<string, unknown>>;
    truncated: boolean;
  } | null;
  chart_ids: string[];
}

export interface NeutralChartSpec {
  chart_id: string;
  analysis_id: string;
  type: "bar" | "scatter" | "kpi" | "gauge" | "pie" | string;
  title: string;
  dataset: Array<Record<string, unknown>>;
  encoding: Record<string, string | string[]>;
  series: Array<{ field: string; name: string }>;
}
```

推荐按以下顺序渲染：

1. 展示 `title`、`generated_at` 和 `executive_summary`。
2. 按 `sections` 原顺序渲染每个章节。
3. `key_metrics` 显示为指标卡，不能依赖固定 key 或擅自改变单位。
4. `table.columns` 决定列顺序，`table.rows` 提供动态行；`truncated=true` 时显示
   “仅展示前 100 行”。
5. 根据章节的 `chart_ids`，从顶层 `charts` 中找到对应图表并渲染。
6. 展示报告 `warnings` 和来源信息 `provenance`。

摘要采用医疗场景的 fail-closed 规则：当
`section.summary_validation.trusted !== true` 时，前端应明确显示校验警告，并以
`key_metrics`、`table` 和 `charts` 的结构化数据为准，不能把该段文本强调为可信结论。
`validation.all_summaries_trusted === true` 时仍可能存在 `LLM_FALLBACK` 或
`SAVED_SUMMARY_REUSED` 警告，不能用 `warnings.length === 0` 代替可信状态判断。

图表是中立 JSON 规格，不是可直接执行的 ECharts 配置：

| `type` | `encoding` 字段 | 推荐展示 |
|---|---|---|
| `bar` | `category`、`values` | 类目轴柱状图；`category` 可能是字符串或字符串数组 |
| `scatter` | `x`、`y`、可选 `size`、`label` | 关联规则散点图 |
| `kpi` | `label`、`value` | 指标卡即可，无需强制使用 ECharts |
| `gauge` | `value`、`label` | 风险仪表盘 |
| `pie` | `category`、`values` | 风险等级饼图 |

`dataset` 是图表数据，`series` 是字段和展示名提示。前端只做字段映射，不应
`eval` 任何返回值，也不应把服务端字符串当作 JavaScript formatter 执行。

风险评分 `risk_score` 是 0~100 分，不是 0~1 概率。费用显示应使用数据返回的
`currency`，不能硬编码人民币；单位为空时也不能自行追加 `%`。

当前 `display.supported_exports` 只有 `json`。前端可下载报告 JSON，但不能把 PDF、
Word 等尚未实现的格式显示为后端原生导出能力。

## 7. 错误处理与重试

错误示例：

```json
{
  "code": 400,
  "message": "参数校验失败",
  "data": {
    "detail": {
      "message": ["Length must be between 1 and 500."]
    }
  },
  "query_time": 0.002,
  "trace_id": "44b46a05adc94a8d"
}
```

| HTTP / `code` | 常见原因 | 前端处理 |
|---|---|---|
| `400` | JSON/Content-Type、未知字段、字段格式、长度或必填项错误 | 显示 `message` 和可读的 `data.detail`；修改参数后再提交 |
| `401` | assistant 凭证缺失或无效 | 不自动循环重试；交由登录/BFF或部署配置处理 |
| `404` | 会话过期，分析或报告不属于该会话 | 会话 404 时清理旧 ID；资源 404 时刷新会话列表 |
| `405` | HTTP 方法错误 | 修正前端路由调用 |
| `409` | 同一 `request_id` 被不同请求复用，或会话版本冲突 | 幂等冲突时更换 ID；其他冲突先刷新会话再重试 |
| `413` | 请求体超过 2 MiB | 缩小请求；聊天消息本身上限为 500 字符 |
| `429` | 同一会话并发请求等待超时 | 禁用重复发送，延迟后用相同请求重试 |
| `500` | 未预期服务错误 | 展示通用错误和 `trace_id`，不要展示服务堆栈 |
| `503` | 依赖未就绪、生产缺凭证配置或会话锁异常 | 指数退避；若持续失败则提示服务暂不可用 |
| `504` | 分析超时 | 建议缩小查询范围，允许用户重试 |

需要同时区分两类失败：

- HTTP 非 2xx：调用本身失败，按上表处理。
- HTTP 200 且 `data.status === "failed"`：编排层成功接收请求，但下游工具执行失败；
  展示 `assistant_message.content`、`warnings` 及其中的追踪号。

推荐对可重试错误使用短指数退避（例如 0.5 秒、1 秒、2 秒，最多 3 次）。只有在
前端没有拿到确定业务结果时，才复用原请求的 `request_id`；用户主动发起新的分析必须
生成新 ID。

## 8. 前端联调检查清单

- 新建会话时不发送自造的 `session_id`，并保存服务端返回值。
- 续聊、恢复和报告请求始终使用同一会话的资源 ID。
- 同一会话发送期间禁用重复提交。
- 网络不确定性重试复用相同 `request_id` 和完全相同的请求体。
- 七种 `status` 均有确定展示分支。
- 始终展示助手文本；结构化分析和报告作为附加区域。
- 不可信摘要有明显警告，结构化数据优先。
- 动态表格和中立图表规格不依赖写死字段，也不执行返回字符串。
- 会话 `404` 时清理本地过期 ID。
- 错误界面保留 `trace_id`，但不暴露 API Key 或内部堆栈。
- 生产浏览器包中不存在共享 API Key。
