# 3.X 模型与智能分析

人员4负责模型与智能分析相关功能，包括基础自然语言意图识别、分析结果文本生成、复杂医疗大数据分析、意图识别优化以及 LLM 本地化部署。模型相关功能位于系统 AI 智能层，与人员3提供的大数据分析服务进行协作，并由人员1负责上层工具调用与应用编排。

系统整体 AI 智能层负责解析用户自然语言查询、获取大数据分析结果并生成文字洞察。项目采用 LangChain、LLM、机器学习及 FastAPI 等技术实现相关功能。

# 3.X.1 基础自然语言意图识别

## 1、功能简单介绍

基础自然语言意图识别用于理解用户输入的自然语言医疗数据查询需求，将用户的自然语言问题转换为系统能够识别的标准化查询意图及相关参数，为后续大数据分析服务调用提供依据。

用户可以直接使用自然语言提出医疗数据分析问题，例如按照疾病、年龄段、医院、年份等条件查询患者数据，系统对用户输入进行语义分析，识别用户希望执行的分析类型，并提取查询所涉及的维度、指标和条件。

项目要求对意图类别和医疗术语范围进行定义，并划分训练集、验证集和测试集，意图识别准确率要求达到 90% 以上。

本功能主要负责\*\*“用户到底想查什么”\*\*，不负责具体调用哪个 API。API 的工具注册、意图与 API 的映射以及参数转换属于人员1的智能工具调用功能。

## 3、用例阐述

**用例名称：** 基础自然语言意图识别

**功能描述：** 用于识别用户自然语言医疗数据查询意图，将用户输入转换为标准化的意图类别及查询参数，为后续大数据分析服务提供输入。

**参与者：** 系统用户、意图识别模型。

**前置条件：**

1. 系统 AI 智能交互功能正常运行。
2. 意图识别模型已经完成训练并加载。
3. 用户已经进入系统交互界面。
4. 大数据分析服务接口处于可调用状态。

### 事件流

#### 2.1 基本流

1）用户在系统交互界面输入自然语言查询内容。

2）系统接收用户输入，并对输入文本进行基本预处理。

3）意图识别模型分析用户输入内容。

4）系统识别用户的查询意图，包括用户希望进行的数据分析类型。

5）系统从自然语言中提取相关查询条件，包括疾病、年龄、医院、年份等可能涉及的查询维度。

6）系统将识别出的意图及查询条件转换为标准化结构。

7）系统将标准化意图结果返回给上层 AI 应用模块。

8）结束用例。

#### 2.2 备选子流

**2.2.1 无法识别用户意图**

1）系统无法从用户输入中确定明确的分析意图。

2）系统返回无法识别的提示信息。

3）提示用户重新描述查询需求。

4）用户重新输入查询内容后重新执行本用例。

**2.2.2 查询条件不完整**

1）系统识别出用户的分析意图，但发现必要查询条件缺失。

2）系统标记缺失的查询参数。

3）将缺失参数信息返回上层应用模块。

4）由上层应用模块决定后续是否向用户请求补充信息。

**2.2.3 输入内容不属于系统支持范围**

1）系统识别用户输入不属于医疗大数据分析范围。

2）系统返回不支持该类型查询的结果。

3）结束本次意图识别。

**成功保证：**

系统能够输出标准化的用户意图及可识别的查询条件；对于无法识别或超出系统范围的输入，系统能够返回明确的异常结果，而不会产生错误的分析意图。

3.X.2 分析结果文本生成

## 1、功能简单介绍

分析结果文本生成功能用于将人员3的大数据分析服务返回的结构化分析结果转换为通俗易懂的自然语言摘要，对分析结果进行解释，使用户能够直接理解医疗大数据分析结果。

项目要求 AI 智能交互模块能够将 API 返回的结构化大数据转化为通俗易懂的文字摘要，并结合医疗业务场景解释分析结果。项目采用 LLM 实现该功能。

该功能的职责重点是\*\*“怎样让模型正确解释数据”\*\*，而不是负责调用分析 API。分析 API 的调用由人员1负责，人员3负责提供稳定的分析数据接口。

## 3、用例阐述

**用例名称：** 分析结果文本生成

**功能描述：** 将大数据分析服务返回的结构化数据转换为自然语言分析摘要，对主要统计结果进行解释，并以通俗易懂的方式向用户呈现。

**参与者：** AI 应用模块、LLM。

**前置条件：**

1. 用户已经完成医疗数据查询。
2. 人员3的大数据分析服务已经返回结构化分析结果。
3. LLM 服务正常运行。
4. 已配置对应的 Prompt 和输出格式。

### 事件流

#### 2.1 基本流

1）AI 应用模块接收大数据分析服务返回的结构化数据。

2）系统整理分析结果中的维度、指标和统计数据。

3）系统按照预先设计的 Prompt 格式构造 LLM 输入。

4）将结构化分析结果和相关上下文发送给 LLM。

5）LLM 对分析结果进行理解和归纳。

6）LLM 生成自然语言分析摘要。

7）系统对生成结果进行基本格式和内容检查。

8）系统将分析结果文本返回给上层应用模块。

9）结束用例。

#### 2.2 备选子流

**2.2.1 分析结果为空**

1）系统接收到的分析结果为空。

2）系统不调用 LLM 生成无依据的分析结论。

3）返回“暂无可用分析数据”等提示。

4）结束用例。

**2.2.2 LLM 调用失败**

1）系统调用 LLM 失败。

2）系统记录模型调用异常。

3）返回文本生成失败提示。

4）结束用例。

**2.2.3 生成结果格式异常**

1）LLM 返回的内容不符合规定格式。

2）系统尝试进行结果格式处理。

3）如果处理成功，则返回标准化文本。

4）如果处理失败，则返回生成异常提示。

**2.2.4 生成结果存在明显幻觉或数据不一致**

1）系统对生成文本中的关键数据进行检查。

2）发现生成文本与输入分析结果存在明显不一致。

3）丢弃异常生成结果。

4）返回重新生成或异常提示。

项目分工明确要求人员4负责 LLM 输入输出格式、Prompt 设计以及幻觉控制和隐私要求。

**成功保证：**

系统根据结构化分析数据生成与原始分析结果一致的自然语言摘要，不自行虚构不存在的数据，并按照规定格式向上层应用返回文本结果。

3.X.3 复杂医疗大数据分析

## 1、功能简单介绍

复杂医疗大数据分析用于在基础统计分析之外，对医疗数据进行进一步的数据挖掘和预测分析。

本功能包含三个主要分析方向：

1. **疾病关联分析**
2. **住院费用预测**
3. **患者再入院风险评估**

项目描述明确将这三项列为二期复杂医疗大数据分析功能，并要求结合医疗业务场景挖掘海量医疗数据价值。

人员4负责其中的特征工程、模型训练和推理，人员3负责协助数据统计和特征准备。

## 3、用例阐述

**用例名称：** 复杂医疗大数据分析

**功能描述：** 对经过预处理的医疗大数据进行复杂的数据挖掘和机器学习分析，实现疾病关联分析、住院费用预测以及患者再入院风险评估。

**参与者：** 系统用户、复杂医疗分析模型。

**前置条件：**

1. 医疗数据已经完成清洗、标准化和结构化存储。

3. 分析模型已经完成训练。

### 事件流

#### 2.1 基本流

1）用户提出复杂医疗数据分析需求。

2）系统识别分析类型。

3）系统获取对应分析所需的数据。

4）系统按照对应分析模型进行特征处理。

5）系统调用相应模型执行推理。

6）根据分析类型生成对应结果。

7）系统返回复杂医疗大数据分析结果。

3）执行疾病之间的关联分析。

4）生成疾病关联关系及分析结果。

5）返回分析结果。

**2.2.2 住院费用预测**

1）系统获取患者相关特征。

2）进行预测模型所需的特征处理。

3）调用住院费用预测模型。

4）模型输出预测费用结果。

5）系统返回费用预测结果。

6）模型评价采用 MAE 等指标进行评估。人员4的模型需求明确规定费用预测需要设计 MAE 等评价指标。

**2.2.3 患者再入院风险评估**

1）系统获取患者相关医疗数据。

2）对输入数据进行特征处理。

3）调用再入院风险评估模型。

4）模型输出患者再入院风险结果。

5）系统返回风险评估结果。

6）模型采用 AUC 等指标进行评价。

**2.2.4 数据不足**

1）系统检查发现分析所需数据不足。

2）系统终止当前分析任务。

3）返回数据不足提示。

**2.2.5 模型运行异常**

1）模型推理过程中发生异常。

2）系统记录异常信息。

3）返回分析失败提示。

**成功保证：**

系统能够根据用户选择的复杂分析类型调用对应分析模型，并返回疾病关联、住院费用预测或患者再入院风险评估结果。

3.X.4 意图识别优化

## 1、功能简单介绍

意图识别优化是在基础自然语言意图识别的基础上，对模型的自然语言理解能力进行增强，使系统能够处理更加复杂、模糊以及包含多个查询维度的医疗数据查询。

项目描述明确要求二期意图识别支持：

- 大数据模糊查询
- 多维度查询意图识别
- 医疗术语联想

并要求将意图识别准确率提升至 90% 以上。

该功能主要通过优化训练数据、特征处理和模型推理方式，提高基础意图识别模型对复杂自然语言查询的理解能力。

## 3、用例阐述

**用例名称：** 意图识别优化

**功能描述：** 对基础自然语言意图识别模型进行优化，使模型能够识别模糊查询、多维度查询以及医疗领域相关术语，提高自然语言查询意图识别准确率。

**参与者：** 系统用户、模型训练工程师、意图识别模型。

**前置条件：**

1. 已经存在基础自然语言意图识别模型。
2. 已经准备训练数据。
3. 已建立训练集、验证集和测试集。
4. 已定义医疗领域意图类别及医疗术语范围。

项目分工明确要求人员4自行定义意图类别和医疗术语范围，并进行训练集、验证集、测试集划分。

### 事件流

#### 2.1 基本流

1）收集并整理自然语言查询数据。

2）根据医疗业务场景划分意图类别。

3）整理医疗专业术语及相关表达。

4）构建训练集、验证集和测试集。

5）对意图识别模型进行训练。

6）使用验证集进行模型参数调整。

7）使用测试集对优化后的模型进行评估。

8）检查模型意图识别准确率。

9）当模型达到要求后，生成优化后的模型。

10）将优化后的模型用于系统意图识别。

#### 2.2 备选子流

**2.2.1 模型准确率未达到要求**

1）使用测试集进行模型评估。

2）发现意图识别准确率低于 90%。

3）分析错误样本。

4）补充或调整训练数据。

5）重新训练模型。

6）再次进行模型评估。

**2.2.2 医疗术语无法识别**

1）测试数据中出现模型无法正确识别的医疗术语。

2）分析术语及上下文。

3）将相关术语加入医疗术语范围或训练数据。

4）重新训练模型。

**2.2.3 多维度查询识别错误**

1）用户输入同时包含多个查询维度。

2）模型未能正确识别所有查询维度。

3）分析错误查询样本。

4）调整多维度意图识别数据及模型。

5）重新进行训练和验证。

**成功保证：**

优化后的模型能够支持模糊查询、多维度查询和医疗术语识别，并满足项目规定的意图识别准确率不低于 90% 的要求。

3.X.5 LLM 本地化部署

## 1、功能简单介绍

LLM 本地化部署用于将开源大语言模型部署到项目本地运行环境中，为系统提供本地自然语言理解和文本生成能力。

项目要求二期将开源 LLM，例如 Qwen、BaiChuan 等进行本地化部署，避免依赖云端接口，提高大数据分析结果文本生成的响应速度，并保障医疗数据隐私。项目要求使用 FastAPI 提供模型服务接口。

人员4负责本地模型部署以及服务接口规范，人员1负责在应用层调用该模型能力。

## 3、用例阐述

**用例名称：** LLM 本地化部署

**功能描述：** 将开源大语言模型部署在项目本地环境中，通过 FastAPI 对外提供统一模型服务接口，为系统提供自然语言理解和文本生成能力。

**参与者：** 模型训练工程师、AI 应用模块、本地 LLM 服务。

**前置条件：**

1. 已选择需要部署的开源 LLM。
2. 本地运行环境满足模型运行要求。
3. 模型文件已经准备完成。
4. 已确定模型输入输出格式。
5. 已确定 FastAPI 服务接口规范。

### 事件流

#### 2.1 基本流

1）模型训练工程师选择需要部署的开源 LLM。

2）准备模型文件及运行环境。

3）加载本地模型。

4）配置模型运行参数。

5）启动 FastAPI 服务。

6）系统开放模型服务接口。

7）AI 应用模块向 FastAPI 服务发送模型请求。

8）本地 LLM 接收输入数据。

9）LLM 执行自然语言理解或文本生成。

10）FastAPI 服务获取模型生成结果。

11）服务按照规定格式返回结果。

12）AI 应用模块接收模型结果。

13）结束用例。

#### 2.2 备选子流

**2.2.1 模型加载失败**

1）系统尝试加载本地模型。

2）模型文件或运行环境存在异常。

3）模型加载失败。

4）系统记录错误信息。

5）返回模型服务不可用状态。

**2.2.2 FastAPI 服务启动失败**

1）系统加载模型成功。

2）启动 FastAPI 服务。

3）服务启动失败。

4）系统记录服务启动异常。

5）重新检查服务配置。

**2.2.3 模型请求参数异常**

1）AI 应用模块发送模型请求。

2）FastAPI 对请求参数进行校验。

3）发现输入参数不符合接口要求。

4）拒绝本次请求。

5）返回参数错误信息。

**2.2.4 模型推理异常**

1）模型正常接收到请求。

2）模型执行推理过程中出现异常。

3）服务捕获异常。

4）返回模型推理失败信息。

**成功保证：**

本地 LLM 能够正常启动，并通过 FastAPI 对外提供统一的模型服务接口，AI 应用模块能够通过接口完成模型调用。医疗数据无需依赖外部云端模型服务，从而满足项目对本地化部署和数据隐私的要求。
