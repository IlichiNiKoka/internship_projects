# 模型与智能分析——用例图文字图例

## 3.X.1 基础自然语言意图识别

**参与者：**
- 系统用户
- 意图识别模型
- 大数据分析服务

**用例：**
- 输入自然语言查询
- 识别用户意图
- 提取查询条件
- 生成标准化意图结果
- 返回识别结果

**用例关系文字说明：**

系统用户进入 AI 智能分析系统，首先输入自然语言查询；系统依次执行识别用户意图、提取查询条件、生成标准化意图结果和返回识别结果。意图识别模型参与用户意图识别过程。

**UML 绘制说明：**

将“输入自然语言查询”“识别用户意图”“提取查询条件”“生成标准化意图结果”“返回识别结果”作为系统内部用例，将“系统用户”作为主要参与者，将“意图识别模型”作为与意图识别过程关联的参与者或外部模型。

## 3.X.2 分析结果文本生成

**参与者：**
- AI 应用模块
- LLM
- 系统用户

**主要用例：**
- 接收结构化分析结果
- 构造模型输入
- 生成分析结果摘要
- 检查生成结果
- 返回文本分析结果

**用例关系文字说明：**

AI 应用模块向 AI 文本分析模块提供结构化分析结果，系统依次执行接收结构化分析结果、构造模型输入、LLM 生成摘要、结果检查与处理以及返回文字分析结果。LLM 参与文本摘要生成过程。

**UML 绘制说明：**

将“接收结构化分析结果”“构造模型输入”“生成分析结果摘要”“检查生成结果”“返回文本分析结果”作为系统内部用例，将“AI 应用模块”作为主要参与者，将“LLM”作为模型参与者。

## 3.X.3 复杂医疗大数据分析

**参与者：**
- 系统用户
- 复杂分析模型
- 大数据分析服务

**用例：**
- 疾病关联分析
- 住院费用预测
- 患者再入院风险评估

**用例关系文字说明：**

系统用户发起复杂医疗数据分析需求，进入复杂医疗大数据分析功能后，根据分析类型分别执行疾病关联分析、住院费用预测或患者再入院风险评估，最终返回相应分析结果。复杂分析模型参与具体分析过程。

**UML 绘制说明：**

建议采用一个总用例图并包含三个子用例。将“疾病关联分析”“住院费用预测”“患者再入院风险评估”作为三个主要用例，将“系统用户”作为主要参与者，将“复杂分析模型”作为模型参与者；大数据分析服务作为外部数据服务参与者。

## 3.X.4 意图识别优化

**参与者：**
- 系统用户
- 意图识别优化模型
- 模型训练工程师

**用例：**
- 模糊查询识别
- 多维度意图识别
- 医疗术语联想
- 模型训练与优化
- 模型效果评估

**用例关系文字说明：**

系统用户对应模糊查询识别、多维度意图识别和医疗术语联想等使用场景；模型训练工程师负责模型训练与优化以及模型效果评估；意图识别优化模型承担优化后的意图识别能力。

**UML 绘制说明：**

将“模糊查询识别”“多维度意图识别”“医疗术语联想”“模型训练与优化”“模型效果评估”作为系统内部用例，将系统用户和模型训练工程师作为主要参与者，并将意图识别优化模型作为模型相关参与者。

## 3.X.5 LLM 本地化部署

**参与者：**
- AI 应用模块
- LLM 本地服务
- 本地开源 LLM
- 模型训练工程师

**用例：**
- 加载本地 LLM
- 配置模型参数
- 启动模型服务
- 接收模型请求
- 执行文本生成
- 返回生成结果
- 服务状态监控

**用例关系文字说明：**

AI 应用模块向 LLM 本地化服务发送模型请求，LLM 本地化服务接收请求后调用本地 LLM 执行文本生成并返回生成结果。模型训练工程师负责模型加载与配置以及服务启动与维护。

**UML 绘制说明：**

将“加载本地 LLM”“配置模型参数”“启动模型服务”“接收模型请求”“执行文本生成”“返回生成结果”“服务状态监控”作为系统内部用例。AI 应用模块、本地开源 LLM 和模型训练工程师作为外部参与者，其中模型训练工程师负责模型加载与配置以及服务启动与维护。
