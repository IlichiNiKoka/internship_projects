# 人员2 · 数据预处理与持久化模块需求

> 编写人：人员2（数据工程师 / 后端工程师）
> 所属项目：智慧医疗大数据与 AI 大模型分析平台
> 模块定位：系统三大核心模块之一（数据预处理与持久化 / 大数据分析服务 / AI 智能交互）
> 数据基础：SPARCS 2021 住院患者出院数据集（200 万+ 条、33 个字段）

---

## 1. 综述

### 1.1 项目介绍

智慧医疗大数据与 AI 大模型分析平台基于真实的医院住院患者出院数据集（Hospital Inpatient Discharge Data），包含患者人口统计学信息、诊断详情（CCSR 编码）、手术操作、疾病严重程度、费用及支付方式等 30 余项关键字段。

数据预处理与持久化模块是平台三大核心模块中的大数据基础模块，负责数十万条（实际 200 万+）原始医疗大数据的读取、清洗、标准化、去重、冗余处理，以及结构化数据的本地持久化存储，保障数据完整性、一致性和可查询性，为后续大数据分析服务提供高质量、高效率的数据基础。

## 2. 功能的简单介绍

| 序号 | 功能 | 功能描述 | 实现技术 | 阶段 |
|---|---|---|---|---|
| 1 | 大数据批量读取 | 高效读取 TSV/CSV 格式的医疗大数据，兼容数十万条记录批量读取，优化读取效率，解决大文件读取卡顿、内存溢出问题 | Python、Pandas | 一期 |
| 2 | 大数据异常处理 | 按照医疗业务规则，批量处理缺失值、异常值，完成数据去重。例如对非新生儿的 Birth Weight 字段设为 N/A，去除重复住院记录 | Python、Pandas | 一期 |
| 3 | 数据类型标准化 | 批量统一数据格式与类型。例如移除 Total Charges 字段中的逗号并转换为浮点数，标准化日期、编码格式 | Python、Pandas | 一期 |
| 4 | 结构化大数据入库 | 将清洗后的结构化数据批量写出为下游可用的存储（一期：清洗后 CSV，分析服务直接读取；二期：MySQL 表结构 + 索引），支撑后续快速查询与分析 | Python、Pandas、Spark CSV（一期）；Python、MySQL、索引优化（二期） | 一期/二期 |
| 5 | 大数据质量评估 | 从完整性、准确性、一致性、时效性四个维度设计评估指标与评分体系，生成可视化数据质量报告 | Python、Pandas、自定义评分算法、ECharts | 二期 |
| 6 | 数据备份与恢复 | 实现数据库自动备份（定时任务）、手动备份，支持海量数据异常情况下的快速恢复 | Python、MySQL、定时任务、HDFS | 二期 |
| 7 | 大数据增量更新 | 自动识别新增数据与历史数据的差异，实现增量入库，避免重复入库 | Python、Pandas、MySQL、Spark | 二期 |

## 4. 用例阐述

### UC1 读取医疗大数据

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 原始 CSV/TSV 文件已存放于 `raw/` 目录 |
| 基本流程 | 1) 递归定位原始数据文件（兼容 7z/RAR 解压后的嵌套同名目录）；2) 全部字段按字符串读入（dtype=str），再由清洗函数显式转型；3) 按 `CHUNK_SIZE=200_000` 分块流式读取，逐块返回 |
| 后置条件 | 数据以分块形式进入内存，峰值内存可控 |
| 异常流程 | 文件不存在时，若配置了 `ARCHIVE_PATH`，调用 7z/RAR 兜底解压；仍找不到则抛 `FileNotFoundError` 并终止 |

### UC2 清洗缺失值 / 异常值

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 原始数据已分块读入 |
| 基本流程 | 1) 文本字段去空白（折叠 NBSP）、缺失统一为 `Unknown`；2) 数值字段缺失置 `NaN`；3) 性别 `M/F/U` 映射为 `Male/Female/Unknown`；4) 急诊标志只保留 `Y/N`，其余置 `Unknown`；5) 整行哈希跨块全局去重 |
| 后置条件 | 字段取值域统一、重复记录被去除 |
| 异常流程 | 脏值、非法值统一归为 `Unknown` 或 `NaN`，不中断流程 |

### UC3 标准化数据类型

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 缺失值/异常值已处理 |
| 基本流程 | 1) 列名统一为 snake_case（空格/连字符/括号转下划线、全小写）；2) 金额字段去千分位逗号转浮点；3) 住院天数、出院年份、严重程度代码、出生体重转可空整型 `Int64`；4) 机构号 / DRG / MDC / 邮编等编码保留字符串原样（含前导零） |
| 后置条件 | 字段类型正确、格式统一，可参与数值计算 |
| 异常流程 | 无法转数值的字段置 `NaN`，不静默四舍五入 |

### UC4 输出结构化数据（一期：清洗后 CSV）

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员（下游大数据分析服务模块依赖本用例结果） |
| 前置条件 | 数据已清洗、标准化 |
| 基本流程 | 1) 按清洗后数据字典定义字段类型（27 字符串 / 4 整型 / 2 浮点）；2) 流式追加写入清洗后 CSV（首块带表头、后续追加）；3) 同步生成处理报告 JSON（原始/清洗行数、去重数、各字段缺失量、关键字段分布、清洗规则摘要）；4) 大数据分析服务（Spark CSV）可直接读取该 CSV，无需重复加载 |
| 后置条件 | 结构化清洗数据落盘至 `processed/*_clean.csv`，可供分析服务查询 |
| 异常流程 | 一期不依赖 MySQL；若二期规划入库，则 MySQL 不可用时降级 SQLite，并记录目标库信息 |

> UC5 / UC6 / UC7 为二期用例，已列入规划但尚未在仓库中实现：

| 用例 | 参与者 | 简述 |
|---|---|---|
| UC5 数据质量评估 | 数据管理员 | 按完整性、准确性、一致性、时效性四维度评分，生成可视化质量报告 |
| UC6 数据备份与恢复 | 数据管理员 | 定时/手动备份数据库，支持异常时快速恢复 |
| UC7 数据增量更新 | 数据管理员 | 识别新增数据差异，增量入库，避免重复导入 |

## 5. 流程图

### 数据预处理与持久化主流程

```text
开始
  │
  ▼
定位原始 CSV（raw/ 递归查找，必要时兜底解压）
  │
  ▼
按 CHUNK_SIZE=200_000 分块流式读取（dtype=str）
  │
  ▼
列名统一 snake_case
  │
  ▼
文本/编码字段清洗（去空白 + 缺失填 Unknown）
  │
  ▼
性别 M/F/U → Male/Female/Unknown
  │
  ▼
急诊标志仅保留 Y/N
  │
  ▼
整数字段去逗号转 Int64（失败置 NaN）
  │
  ▼
金额字段去逗号转浮点
  │
  ▼
整行哈希是否已存在？
  ├─ 是 → 丢弃重复行
  └─ 否 → 保留该行
       │
       ▼
流式追加写入 processed/*_clean.csv
       │
       ▼
是否还有下一块？
  ├─ 是 → 回到「按 CHUNK_SIZE 分块读取」
  └─ 否 → 生成处理报告 JSON（processed/processing_report.json）
            │
            ▼
          结束
```

## 附录 B：验收标准

1. 能够分块读取 200 万+ 行 CSV/TSV 数据，不出现内存溢出；
2. 清洗后字段类型一致、值域统一：金额为数值、缺失值统一为 `Unknown`/`NaN`、编码保留前导零；
3. 重复住院记录被去除，去重数量可审计（见 `processing_report.json.rows.duplicate_rows_removed`）；
4. 清洗结果成功写出至 `processed/*_clean.csv`，分析服务（Spark）可直接读取并完成多维度聚合查询；
5. 入库过程生成处理报告 `processing_report.json`，记录原始/清洗/去重行数与耗时、各字段缺失量、关键字段取值分布。
