## 3.2 数据预处理与持久化模块（人员2）

### 总述

数据预处理与持久化模块是智慧医疗大数据与 AI 大模型分析平台三大核心模块中的大数据基础模块，负责 SPARCS 2021 住院患者出院数据集（200 万+ 行、33 字段）的读取、清洗、标准化、去重与持久化存储，保障数据完整性、一致性与可查询性，为后续大数据分析服务模块提供高质量、高效率的数据基础。总述由项目大概介绍、功能架构图、技术层次架构图三部分组成。

#### 1. 项目大概介绍

智慧医疗大数据与 AI 大模型分析平台基于真实的医院住院患者出院数据集（Hospital Inpatient Discharge Data），包含患者人口统计学信息、诊断详情（CCSR 编码）、手术操作、疾病严重程度、费用及支付方式等 30 余项关键字段。数据预处理与持久化模块作为平台的大数据基础模块，负责数十万条（实际 200 万+）原始医疗大数据的读取、清洗、标准化、去重、冗余处理，以及结构化数据的本地持久化存储，为后续大数据分析服务模块提供高质量、高效率的数据基础。

> 一期实现采用「清洗后 CSV + Spark 直接读取」的轻量化持久化方案，二期规划接入 MySQL/HDFS（脚本预留 MySQL/SQLite 兜底入口）。

## UC1 读取医疗大数据（功能 1）

### 功能简单介绍

大数据批量读取是数据预处理与持久化模块的入口功能。系统在 `raw/` 目录下递归查找原始 CSV/TSV 文件（兼容 7z/RAR 解压后的嵌套同名目录结构），按 `CHUNK_SIZE=200_000` 分块流式读取，全部字段统一以字符串形式读入（`dtype=str`），再由清洗函数显式转型，避免 Pandas 类型推断在大数据上出现意外行为，解决 832 MB 大文件一次性载入导致的内存溢出与读取卡顿问题。

### 用例阐述

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 原始 CSV/TSV 文件已存放于 `raw/` 目录 |
| 基本流程 | 1) 递归定位原始数据文件（`find_source_csv` 自动取体积最大的 CSV，避免误取）；2) 全部字段按字符串读入（`dtype=str`），由清洗函数显式转型；3) 按 `CHUNK_SIZE=200_000` 分块流式读取，逐块返回，峰值内存仅取决于单块大小 |
| 后置条件 | 数据以分块形式进入内存，峰值内存可控 |
| 异常流程 | 文件不存在时，若配置了 `ARCHIVE_PATH`，调用 7z/RAR 兜底解压；仍找不到则抛 `FileNotFoundError` 并终止 |

### 流程图

```text
开始
  │
  ▼
递归查找 raw/ 下的 CSV（取体积最大者）
  │
  ▼
是否找到？
  ├─ 否 → 尝试 7z/RAR 兜底解压 ARCHIVE_PATH
  │       └─ 仍找不到 → 抛 FileNotFoundError → 结束
  └─ 是 → pd.read_csv(chunksize=200_000, dtype=str)
          │
          ▼
        迭代器逐块返回（首块带表头）
          │
          ▼
        结束
```

## UC2 清洗缺失值 / 异常值（功能 2）

### 功能简单介绍

大数据异常处理按医疗业务规则批量处理缺失值、异常值，并完成跨块全局去重。文本/分类字段去空白（折叠 NBSP）并将缺失统一为 `Unknown`；数值字段缺失置 `NaN`；性别 `M/F/U` 映射为 `Male/Female/Unknown`；急诊标志只保留 `Y/N`，其余置 `Unknown`；最后用整行哈希 + 全局已见集合做流式跨块去重，去掉完全重复的住院记录。

### 用例阐述

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 原始数据已分块读入 |
| 基本流程 | 1) 文本字段去空白（折叠 NBSP）、缺失统一为 `Unknown`；2) 数值字段缺失置 `NaN`；3) 性别 `M/F/U` 映射为 `Male/Female/Unknown`；4) 急诊标志只保留 `Y/N`，其余置 `Unknown`；5) 整行哈希跨块全局去重 |
| 后置条件 | 字段取值域统一、重复记录被去除 |
| 异常流程 | 脏值、非法值统一归为 `Unknown` 或 `NaN`，不中断流程 |

### 流程图

```text
开始
  │
  ▼
对当前块调用 clean_chunk()
  │
  ▼
文本/编码字段 → clean_text（去空白 + 缺失填 Unknown）
  │
  ▼
性别 → standardize_gender（M/F/U → Male/Female/Unknown）
  │
  ▼
急诊标志 → standardize_yn（仅保留 Y/N）
  │
  ▼
计算整行哈希 → 与全局 seen_hashes 比对
  ├─ 已存在 → 丢弃该行
  └─ 未出现 → 保留该行，哈希入集合
       │
       ▼
     结束
```

## UC3 标准化数据类型（功能 3）

### 功能简单介绍

数据类型标准化批量统一数据格式与类型：列名统一为 snake_case（空格/连字符/括号转下划线、全小写）；金额字段去千分位逗号转浮点；住院天数、出院年份、严重程度代码、出生体重转可空整型 `Int64`；机构号 / DRG / MDC / 邮编等编码保留字符串原样（含前导零）。无法转数值的字段置 `NaN`，不静默四舍五入，保证字段类型正确、格式统一，可参与数值计算。

### 用例阐述

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员 |
| 前置条件 | 缺失值/异常值已处理 |
| 基本流程 | 1) 列名统一为 snake_case；2) 金额字段去千分位逗号转浮点；3) 住院天数、出院年份等转可空整型 `Int64`；4) 机构号 / DRG / MDC / 邮编等编码保留字符串原样（含前导零） |
| 后置条件 | 字段类型正确、格式统一，可参与数值计算 |
| 异常流程 | 无法转数值的字段置 `NaN`，不静默四舍五入 |

### 流程图

```text
开始
  │
  ▼
normalize_column_name 列名统一 snake_case
  │
  ▼
分字段处理：
  ├─ TEXT_COLUMNS  → clean_text
  ├─ CODE_COLUMNS  → clean_text（保字符串）
  ├─ PAYMENT_COLUMNS → clean_text
  ├─ INT_COLUMNS   → to_nullable_int
  └─ MONEY_COLUMNS → to_money
  │
  ▼
特殊映射：
  ├─ gender → standardize_gender
  └─ emergency_department_indicator → standardize_yn
  │
  ▼
返回清洗后的 DataFrame
  │
  ▼
结束
```

## UC4 输出结构化数据（功能 4，一期：清洗后 CSV）

### 功能简单介绍

结构化大数据入库将清洗后的结构化数据批量写出为下游可用的存储。一期采用「清洗后 CSV」方案：按清洗后数据字典定义的 33 字段类型，流式追加写入 `processed/*_clean.csv`（首块带表头、后续追加），同步生成 `processed/processing_report.json` 处理报告（原始/清洗行数、去重数、各字段缺失量、关键字段分布、清洗规则摘要）。分析服务（`SparkDataProvider`）通过 `SPARCS_SCHEMA` 显式声明字段类型后直接读取该 CSV，无需重复清洗与加载。二期规划接入 MySQL 表结构 + 索引（脚本预留 MySQL/SQLite 兜底入口）。

### 用例阐述

| 项目 | 内容 |
|---|---|
| 参与者 | 数据管理员（下游大数据分析服务模块依赖本用例结果） |
| 前置条件 | 数据已清洗、标准化 |
| 基本流程 | 1) 按清洗后数据字典定义字段类型（27 字符串 / 4 整型 / 2 浮点）；2) 流式追加写入清洗后 CSV（首块带表头、后续追加）；3) 同步生成处理报告 JSON（原始/清洗行数、去重数、各字段缺失量、关键字段分布、清洗规则摘要）；4) 大数据分析服务（Spark CSV）可直接读取该 CSV，无需重复加载 |
| 后置条件 | 结构化清洗数据落盘至 `processed/*_clean.csv`，可供分析服务查询 |
| 异常流程 | 一期不依赖 MySQL；若二期规划入库，则 MySQL 不可用时降级 SQLite，并记录目标库信息 |

### 流程图

```text
开始
  │
  ▼
清洗后 DataFrame 是否还有下一块？
  ├─ 否 → 写入处理报告 JSON → 结束
  └─ 是 → 流式追加写入 processed/*_clean.csv
          ├─ 首块 → 带 header
          └─ 后续 → mode='a', 不带 header
          │
          ▼
        累计缺失量、关键字段分布
          │
          ▼
        回到「是否还有下一块」
```
