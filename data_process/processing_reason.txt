医养项目数据处理原因说明

1. 原始数据文件为压缩包中的大规模医院住院出院数据 CSV，体积约 832 MB，单次全量读取会占用较多内存，并且存在明显的分块大数据处理需求。
2. 数据中金额字段（Total Charges、Total Costs）以逗号分隔字符串形式出现，需要统一清洗为数值类型，否则后续统计、汇总和模型训练会出错。
3. 分析字段中存在缺失值、空字符串和非标准值，例如 Payment Typology 2/3、Birth Weight、Gender、Race、Ethnicity 等字段，需要统一填充和标准化。
4. 该项目的后续分析（按年龄、病种、支付方式、费用分布等维度进行统计和可视化）要求字段类型一致、编码统一、值域清晰，避免分析结果偏差。
5. 医疗大数据在真实业务中需要保证质量，只有对原始记录进行清洗、标准化、去重和一致性校验，才能支撑后续 AI 分析、报告生成和大屏展示。

处理方案概述

- 使用 7z 解压 RAR 压缩包，定位真实的 CSV 数据文件。
- 按 200,000 行分块读取，避免一次性加载大文件导致内存压力。
- 对字段名、缺失值、金额、支付方式、性别、年龄等字段进行标准化处理。
- 统一写出清洗后的 CSV 文件，并输出处理报告 JSON，记录原始行数、清洗后行数、去重数量和处理理由。

具体采用的方法包括：

列名统一化

把字段名中的空格、-、/、括号等统一整理为统一命名规则
例如：
“Total Charges” -> “total_charges”
“Zip Code - 3 digits” -> “zip_code_3_digits”
缺失值处理

把空字符串、NaN、None 等统一处理为 Null/Unknown
例如支付方式、种族、性别字段缺失时统一填充为 “Unknown”
金额字段规范化

去除金额中的逗号和非数字字符
将字符串型金额转成浮点数
例如：
“320,922.43” -> 320922.43
分类字段标准化

对 Gender 做映射：
M/F -> Male/Female
对支付方式等字段做统一值域规范化，避免“Medicare”“Medicaid”“Unknown”等混杂
去重处理

用 drop_duplicates() 去掉重复住院记录，避免重复统计
分块处理

使用 pd.read_csv(..., chunksize=200000) 分批读取大文件
这是为了应对 200 万+ 行大数据的内存压力

工程文件
- medical_data_pipeline.py：数据清洗与标准化主脚本。
- processing_report.json：处理结果报告（脚本运行后生成）。

适用场景
- 适用于医疗大数据项目的原始数据接入、质量处理、数据仓库加载、可视化分析和模型训练前的数据准备。
